# AGENTS.md

Guidance for AI agents and contributors working on **Blaze Toolbox**: on-device photo and PDF tools.
Next.js 15 (App Router) + React 19 + TypeScript. No backend. Files never leave the user's device.

## Project map
- `lib/tools.ts` — the list of tools (`slug`, `name`, `blurb`, `meta`, `cat`, `mode`, `tags`) and the `CATEGORIES`/`MODES`/`TAGS`. Home grid and static routes come from this.
- `app/page.tsx` — home. `app/tools/[slug]/page.tsx` — one static page per tool. `app/privacy/page.tsx` — the privacy page (static, long-form `.prose`), linked from the header nav and footer.
- `components/Shell.tsx` — site frame: sticky header, `<main>`, footer. `wide` prop widens the container.
- `components/tools/Workbench.tsx` — the simple tools (compress, image convert, HEIC to JPG, SVG to PNG, favicon pack, circle crop, watermark, Base64, PDF to image, image to PDF, PDF grayscale, PDF merge/split/rotate/unlock/lock, video to audio, audio to video, trim audio & video).
- `components/tools/ImageResize.tsx` — the image resize tool: cropperjs crop stage (free + fixed ratios, rotate/zoom/reset) with optional width/height typing and a format/quality output. Rendered for `image-resize` in `app/tools/[slug]/page.tsx`; it is no longer in `Workbench`.
  - Default output format follows the input: JPG for photos, PNG only for PNG/GIF (transparency). Never default a photo to PNG — lossless PNG can turn a 150 KB JPEG into multi-MB output. The UI hints at this.
- `components/tools/FileHash.tsx` — the file hash & compare tool (`file-hash`), rendered in `app/tools/[slug]/page.tsx` (not in `Workbench`, because the output is text hashes, not downloadable files). SHA-1 / SHA-256 / SHA-512 come from the browser's own **Web Crypto** (`crypto.subtle.digest`) — no library and no download; **MD5 is not in Web Crypto**, so it is computed by a small self-contained `md5()` in the same file (validated against the RFC 1321 vectors and 300 random-length fuzz cases vs Node's `crypto` — do not replace it with a dependency). Picking two or more files adds a verdict banner (all files identical / not all the same) and a `same`/`different` tag per file, judged by SHA-256; every hash has a Copy button.
- `components/tools/PassportSheet.tsx` + `passport.module.css` — the passport photo sheet (crop, MaxRects packing, PDF).
- `app/globals.css` — global design tokens and layout.

## Home categories
- Every tool in `lib/tools.ts` has a `cat`: `everyday` (normal users), `edit` (photo/image editing), or `dev` (developer/technical). `CATEGORIES` holds the section order, titles and descriptions.
- The home page renders one `.tools` auto-fit grid per category with a `.tools-head` heading. Keep that order (everyday first, then editing, then developer). Adding a tool only needs a `cat` — no hard-coded lists. Same `.cell` markup, so the fluid rules below apply automatically.
- The home list is rendered by `components/ToolSearch.tsx` (a client component) rather than `app/page.tsx` directly, so the whole tool list can be filtered in place. It keeps the same `.tools-section` / `.tools-head` / `.cell` markup. The search is a plain case-insensitive AND-of-words filter over `name + blurb + meta + slug + cat`, so typing “pdf”, “passport” or “resize” narrows the cards live and empty sections disappear; an empty query shows everything. `/` focuses the box, `Escape` clears it. It is all client-side — no index is fetched. The sticky search bar sits just below the header (`.search`, `top:4.75rem`).
- Below the search box is a **file-type chip row** (`.chips`, `All` + one `.chip` per media type). Every tool has `tags: MediaTag[]` (`image` / `pdf` / `video` / `audio` / `text` / `file`), the union of what it takes in and gives out — e.g. `passport-photo` is `["image", "pdf"]`, `image-to-base64` is `["image", "text"]`, and `file-hash` is `["file"]` (the catch-all `Any file` chip for tools that take any type). `All` is on by default (no filter); any number of chips can be active at once and a tool shows only if it has **all** of the picked tags (**AND**) — e.g. *Video* + *Audio* lists only tools tagged with both. The chip set is derived from `TAGS` (`lib/tools.ts`) but only tags that at least one tool actually uses are rendered, so there is no dead chip until a tool exists — `Video` and `Audio` only appeared once `video-to-audio` shipped. Search words and chips combine (AND). Add a tag by giving a tool a `tags` entry — no hard-coded chip lists.
- Every tool also has a `mode`: `local`, `cloud`, or `hybrid`. `components/ModeTag.tsx` renders a small badge (icon + label) at the top-right of each card via `MODES`. **Every current tool is `local`** — nothing is uploaded and there is no server processing, so do not invent `cloud`/`hybrid` labels. If a real server-backed tool is added later, set its `mode` and the badge/icon already exist. Never relabel a local tool as cloud.

## Layout rules (important)
The site is a **plain, fluid website**. It must look right at any viewport width and any browser zoom (25% to 500%).
- Do NOT bring back graph-paper backgrounds, rulers on the page chrome, floating "sheets", or fixed-width cards.
- Size with `rem`, `%`, `clamp()`, `min()`, `max()`, `vw`/`dvh`. Avoid fixed `px` widths/heights for layout (hairlines and borders are fine).
- Page containers use `.wrap` (`--maxw` grows with the viewport) and `.wrap.wide` for tool pages that need room.
  Header, main and footer share the same container so their left edges align.
- Grids reflow by themselves: `repeat(auto-fit, minmax(min(100%, Xrem), 1fr))`. Avoid hard-coded column counts and magic breakpoints.
- The one structural breakpoint is `62rem` (passport tool switches from side-by-side to stacked). Use `rem` in media queries so it follows zoom.
- Every flex/grid child that holds text or inputs needs `min-width: 0`. No horizontal page scroll at 320px.
- Touch targets are at least `2.75rem` high. Respect `prefers-reduced-motion`.

## Passport tool: preview must fit the screen
- The tool (`.app`) is sized to the screen: `--app-h: clamp(26rem, calc(100dvh - 9rem), 200rem)`. The preview column is sized to the A4 page ratio (`--main-w`); the controls panel takes all the remaining width. The title is compact on this page.
- The A4 preview auto-fits **by width and by height** (see the `calc` effect in `PassportSheet.tsx`), so one whole sheet is visible with no scrolling by default.
  `Fit` resets to this; `+` / `-` zoom from there.
- If you add chrome above the tool, update the `9rem` offset in `passport.module.css` (two places) to match.
- Print: `body.ps-printing` hides page chrome and prints only the A4 pages. Keep that working.

## Help popups (passport tool)
- The round `i` buttons beside Page margin, Set each side separately and Gap open a dialog with an illustration and a short text (`HELP` in `PassportSheet.tsx`).
- The illustration is drawn in code as inline SVG (`HelpDiagram`): an A4 sheet with placeholder passport photos (unknown-person silhouette) and the explained part highlighted. No image files, so nothing to load. Add a topic by adding an entry in `HELP` and a branch in `HelpDiagram`.

## Simple tool pages (Workbench)
- `.wb` is an auto-fit grid: controls (`.wb-in`) and result (`.wb-out`) sit side by side when there is room and stack on phones. No breakpoint needed.
- Keep it that way: new simple tools plug into `Workbench.tsx` and inherit this layout.
- Multi-file tools (`cfg.multi`) **append**: re-picking the file dialog adds more instead of replacing. Selected files show as a `.picks` list with a ✕ remove button each, and tools where order matters (`pdf-merge`, `image-to-pdf`, `pdf-page-numbers`) also get ▲▼ to reorder — `files` order is the output order. Duplicates (same name+size+lastModified) are ignored. Single-file tools (`multi: false`) still replace on re-pick. `pdf-merge` refuses fewer than two PDFs. **Every tool shows the picked file's size** next to its name via `.fsz` (KB/MB): the drop zone shows `name + size` for single-file tools and `N files ready + total` for multi-file ones, and each `.picks` row shows its own size. `image-resize` and the passport tool show the same `.fsz` next to their picked file.
- Tools handled here: compress, compress to a target size, image convert, HEIC to JPG, SVG to PNG, favicon pack, circle crop, watermark, image to Base64, PDF to image, image to PDF, PDF compress, PDF grayscale, PDF merge, PDF split, PDF rotate, PDF unlock, PDF lock, PDF page numbers, video to audio, audio to video, trim audio & video.
- **Compress to a target size** (`image-target-size`) is the same canvas encoder driven by a number instead of a slider: `shrinkToTarget()` binary-searches the highest JPEG/WebP quality that still fits the target, and if even `MIN_QUALITY` (28%) is too big it steps the pixel size down (`× 0.82` per pass) until it fits or the long edge hits `MIN_LONG_EDGE` (320 px). The target is clamped to **1 KB – 20 MB** (`TARGET_MIN`/`TARGET_MAX`) — `clampTarget()` runs on blur and on unit change (and `want` is clamped again at compute), so an empty, negative or oversized entry can never go outside that range. It is **single-file** (`multi: false`, re-pick replaces), unlike the batch compress tool. **A file that is already at or under the target (or that re-encodes no smaller) is left untouched** — the original is handed back as-is with its own name, so the tool never inflates a small file; only files bigger than the target are encoded. The result note says “Already … left untouched”, “Fits <target> …”, or, if the target is impossible, the smallest it could make. JPG or WebP only (lossless PNG cannot hit a byte target). `drawFrom(src, w, h, fill)` is the shared downscaler — it white-fills for JPG and keeps alpha for WebP. A **“Reach the target exactly”** checkbox (`pad`) handles the opposite direction, a *minimum* size: when a photo is already under the target, `padToTarget()` adds invisible filler so the file hits the target without changing a pixel — JPEG gets zero-filled `COM` segments before the scan (`jpegScanStart` finds SOS), PNG gets one zero-filled ancillary `blaz` chunk before `IEND` (correct CRC via `crc32`), and everything else (incl. WebP, where an unknown chunk is rejected by libwebp) gets trailing zero bytes, which decoders ignore. Validated round-trip with Pillow: all three formats decode identically after padding. Keep `pad` **off** by default so the common “must be ≤ X KB” case never inflates a file.
- **Add page numbers** (`pdf-page-numbers`) uses `pdf-lib`: for each page it draws real text with `page.drawText` at a position chosen from 11 spots (top/middle/bottom × left/center/right, plus `outside` = odd pages right, even pages left). The pattern supports `{NUM}` and `{CNT}` (and `{n}`/`{total}`); number style is arabic (with optional leading-zero `digits`), roman, or alpha; spacing is in millimetres (`MM = 72 / 25.4`). Standard fonts only (Helvetica / Times / Courier, bold + italic variants). `firstPage`/`lastPage` skip pages; `firstNumber` offsets; `continuous` carries the count across multiple files and makes `CNT` the total across all files. Text width comes from `font.widthOfTextAtSize`. This mirrors PDF24's option set — note PDF24 does the work on its servers; ours stays on the device.
- Image resize is its own component (`ImageResize.tsx`, cropperjs); see the project map. Keep typing the output size optional — leaving width and height empty keeps the cropped pixels.
- New controls live in the `.opts` auto-fit grid (`label` with input/select/range/checkbox) so they reflow and keep `2.75rem` touch targets. Text, password and colour inputs are styled globally.
- **PDF compress** (`pdf-compress`) has two modes.
  - **Optimize only** (default) is **lossless structural compression** via the same qpdf wasm (`compressPdf()`): `--object-streams=generate --recompress-flate --compression-level=9 --compress-streams=y --remove-unreferenced-resources=yes`. It only repacks the file structure and re-deflates streams — content streams, fonts, text, vectors and annotations are copied through.
  - **Compress** additionally re-encodes the **photos embedded in the PDF** (`collectPdfPhotos` → `encodePdfPhotos` → `applyPdfPhotos`): every `/DCTDecode` image XObject without an `SMask`/`Mask` (and ≥ 2 KB) is decoded through an `<img>`, drawn to a canvas and re-encoded as JPEG at the chosen quality (or, in **Target file size** mode, at the highest quality / largest pixels that still fit `pdfToTarget()`'s budget), then the image stream is swapped in place with `ctx.assign`. It is driven by a `Shrink by` choice of **Quality** (`pcQ`, 20–90%) or **Target file size** (`clampPdfTarget`, 1 KB – 100 MB). Photos the browser cannot decode (CMYK, exotic JPEGs) are skipped, and a re-encoded photo is only kept when it is actually smaller than the original.
  - **Either way text, fonts and vectors are copied through — the words stay selectable and pages are never rasterised.** Do not swap in a “render each page to an image” pipeline (that is `pdf-to-image`, a different tool). Real gains depend on the source: 37–47% on loose text PDFs from the structure alone, and the photo mode adds much more on scanned/photo PDFs (a 2 MP q92 photo page went ~400 KB → ~70 KB after re-encode + downscale). When the result is not smaller the original is handed back untouched (“Already well optimized”). `--optimize-images` / `--jpeg-quality` are **not** available in this qpdf wasm build (no libjpeg) — that is exactly why the photo mode re-encodes in the browser with canvas instead. If a PDF needs a user password qpdf exits 2 and the error tells the user to unlock it first.
- **Video to audio** (`video-to-audio`) pulls the audio track out of a video and drops the picture, all on the device. **MP3 and WAV** use the browser's own decoder (`decodeAudio` → `AudioBuffer`) plus `wavBlob()` (a hand-written 16-bit PCM WAV) and `mp3Blob()` (`@breezystack/lamejs`, imported only when MP3 is picked) — instant, no download. If the browser cannot decode the container (mkv/avi/flv) it silently falls back to the ffmpeg path. **Every other format** (M4A/AAC, OGG/Vorbis, OPUS, FLAC) — and that fallback — go through **ffmpeg.wasm** (`getFfmpeg()`): the single-thread core `@ffmpeg/core@0.12.6` is fetched once from unpkg (both files through `downloadParts`, one ~31 MB progress bar) and cached, and the instance is memoised in `ffmpegPromise`. `ffmpegExtract()` writes the file into the wasm FS and runs `-i in -vn <encoder> out.ext` (`ffArgs` maps format → encoder: libmp3lame / aac / libvorbis / libopus / flac / pcm_s16le). Confirmed the core ships all of those encoders plus the mkv/ogg/webm/mov/mp4 muxers. **Nothing is uploaded** — only the engine binary is downloaded — so the tool stays `mode: local`. Output format (`vaFmt`) and bitrate (`vaBitrate`, lossy formats only) are user-chosen. ffmpeg is lazy (`await import` inside the branch), so it never bloats the page. Since the worker/ffmpeg load only runs in a real browser, re-test this tool in a browser after any change.
- **Audio to video** (`audio-to-video`) puts an audio track on a still frame and encodes a real **MP4** (H.264 + AAC) with the same ffmpeg.wasm engine. The frame is drawn in a canvas at the chosen size (`VIDEO_SIZES`: 1920×1080, 1280×720, 1080×1080, 1080×1920, 854×480) — a plain black or white fill, or a picture the user picks (`makeBgBlob` → `solidCanvas` / `fitCanvas` with a cover/contain fit) — and handed to ffmpeg as one looping PNG (`-loop 1 -framerate 25 -i bg.png`), so **no ffmpeg filters are needed** (the `color`/`scale` filters are avoided on purpose). `ffmpegAudioToVideo()` maps the image as input 0 and the audio as input 1 (`-map 0:v:0 -map 1:a:0`), encodes `libx264 -preset ultrafast -tune stillimage -crf 26 -pix_fmt yuv420p` (ultrafast, because the frame never changes so a slower preset buys little for a lot of wasm time) + `aac -b:a <vaBitrate>k`, and writes `-movflags +faststart`. The frame rate is user-chosen (`avRate`: 25/30/15/10 fps) — lower is faster and smaller. **A looping image never ends, so `-shortest` alone does not stop the video at the audio's length** (it produced a 14 s file for a 6 s track) — the output length is pinned with `-t <duration>` (the length from `mediaDuration()`) plus `-fflags +shortest -max_interleave_delta 0`, falling back to plain `-shortest` only when the length is unknown. Confirmed the core ships `libx264`, `aac`, the `image2` demuxer and `faststart`. Output is always `.mp4`. `mode: local` — only the engine binary is downloaded. The extra background picture is a separate `<input type="file">` (`avBgFile`), not part of the main `files` picker.
- **Trim audio & video** (`trim-media`) cuts a single audio or video file with ffmpeg.wasm. `mediaDuration()` reads the length in the browser via a hidden `<audio>`/`<video>` element (a `useEffect` stores it in `tmDur` and the hint shows it); `parseTime()` accepts `ss`, `m:ss` or `h:mm:ss`. Two modes: **Trim one part** (`tmFrom`/`tmTo`, empty To = end of file) or **Split into parts** (`tmSplit`: equal `tmParts`, or `tmEvery` seconds each). **Trim has a `tmSpeed` choice — `copy` (default) or `encode`.** `copy` streams the packets through with `-c copy` (no re-encode): nearly instant and lossless, but the cut lands on the nearest keyframe before the start (can be a couple of seconds off). `encode` re-encodes (`libx264`/`aac` for video, the format's encoder for audio) so the cut is frame-accurate. If a copy fails (a codec/container combo the output cannot hold, e.g. some mkv→mp4 cases) it **automatically retries that segment with the encoder**, and the result note says whether it was copied or re-encoded. **Split always re-encodes** — copied segments would each snap to the same keyframe and overlap. `ffmpegTrim()` writes the input once and loops `-ss <start> -i in … -t <dur> out`, one exec per segment, with `ffProg` mapping each exec's progress onto the overall bar. Two arg-order gotchas, both verified against real ffmpeg: **`-t` must come after `-c copy`** (with it before the copy options a 1.5 s cut came out ~2.9 s long), and **`-avoid_negative_ts make_zero` must not be used with the copy path** (it also made the output overshoot). `outExt()`/`trimEncoder()` keep the input's own format where ffmpeg can write it (audio → mp3/m4a/ogg/wav/flac by extension; anything else → mp3) and always produce **MP4** for video. `mode: local`.
- Unlock PDF uses **qpdf compiled to WebAssembly** (`@neslinesli93/qpdf-wasm`), loaded lazily only inside that branch. The 1.3 MB `qpdf.wasm` is committed at `public/qpdf/qpdf.wasm` and located via `locateFile: () => "/qpdf/qpdf.wasm"`. It runs `qpdf --decrypt [--password=…] -- in.pdf out.pdf` in the wasm FS and returns the plain bytes. This is what reliably handles real-world protected PDFs (xref streams, AES-256, owner-only restrictions) — plain `pdf-lib` / `@cantoo/pdf-lib` leave modern files encrypted on save, so don't switch back. It removes owner/permission restrictions (empty user password) and removes a user password only when the user supplies it. **Lock PDF** uses the same wasm: `qpdf --encrypt <password> <password> 256 [--print=none] [--extract=n] -- in.pdf out.pdf` (AES-256; user and owner password are the same). Never claim to crack an unknown password — a PDF no reader can open without the password cannot be unlocked without it.
- **PDF grayscale** (`pdf-grayscale`) uses **sumi compiled to WebAssembly** (MIT Rust, `github.com/champierre/sumi`) — not pdf.js rasterising. sumi rewrites only the colour operators to DeviceGray (it also switches `cs`/`CS` and their `sc`/`scn` operands to a single gray value), so text, fonts, vectors, links and annotations are copied through: the output is true grayscale and the words stay **selectable and searchable**. It never uploads anything. The glue is loaded at runtime from `public/sumi/sumi_wasm.js` through a `webpackIgnore` dynamic import in `lib/sumi.ts` (so it stays out of the bundle); the wasm is `public/sumi/sumi_wasm_bg.wasm` (~1 MB, served as `application/wasm`). The wrapper crate and build steps live in `wasm/` (see `wasm/README.md`). **Do not go back to the old "draw each page onto a canvas, grey the pixels, embed a JPEG" pipeline** — it loses all text on every file and inflates the size (benchmarked ~4.5x, text lost on 950/950 files). The UI offers a Grayscale tone model: Luma (PDF spec) or Colorimetric (closer to print).

## Loading rules (keep the site light as tools grow)
- Every tool page is static, but nothing is fetched until the user opens it: all `<Link>`s use `prefetch={false}`.
- Tool components are loaded with `next/dynamic` in `app/tools/[slug]/page.tsx`, so opening one tool never downloads another tool's code. Do not import tool components statically there.
- Tool-only CSS and libraries (e.g. `cropperjs` and its CSS) are imported inside that tool's component, never in `layout.tsx`.
- Heavy libs used on a button press (`pdf-lib`, `pdfjs-dist`) stay behind `await import(...)`.

- Loading UI: there is no `loading.tsx`, so the current page stays on screen while the next one loads. Put `<LinkPending variant="card|inline|bar" />` (uses `useLinkStatus`) inside a `<Link>` to show the indicator (top bar + document/photo animation) right where the user clicked. Keep it CSS-only and respect `prefers-reduced-motion`.
- Never spin forever: after a new deploy an open tab can point at old hashed chunks. `components/ChunkGuard.tsx` (mounted in `layout.tsx`) reloads once on a chunk-load error, and `LinkPending` swaps "Opening..." for a Reload button after 8s, then auto-reloads. `app/error.tsx` + `app/global-error.tsx` give a reload path too. Keep these.
- **Global download indicator**: `lib/loadlog.ts` is a framework-agnostic task store (`startTask` / `updateTask` / `endTask`, `withLoad`, `loadLib`, `fetchProgress`, `downloadParts`). `components/LoadIndicator.tsx` is mounted once in `app/layout.tsx` and shows a fixed bottom-right toast with a **live progress bar** whenever a package is being pulled from the web — so users can see it is a published library download, not injected code. Every runtime download reports here: the **qpdf** wasm (`/qpdf/qpdf.wasm` is pre-fetched with progress and passed to emscripten via `locateFile` → blob URL), the **sumi** wasm (`/sumi/sumi_wasm_bg.wasm`, pre-fetched → blob URL), and the **ffmpeg** core (both files from unpkg via `downloadParts`, shown as one ~31 MB bar). Heavy dynamic imports (pdf.js, pdf-lib, heic2any, JSZip, lamejs, `@ffmpeg/ffmpeg`, `@ffmpeg/util`, `@neslinesli93/qpdf-wasm`) go through `loadLib(key, label, importer)`, which shows an indeterminate bar only the first time it really loads and reuses the cached promise after. The toast says *"downloading a package from the web. Nothing from your device is sent."* Keep new wasm/library loads going through this so the transparency stays complete. The toast is hidden in print.

## Adding a tool
1. Add an entry to `TOOLS` in `lib/tools.ts` and an icon in `components/Icon.tsx`.
2. Simple tool: add a config in `Workbench.tsx`. Complex tool: new component in `components/tools/`, then render it in `app/tools/[slug]/page.tsx`.
3. Everything runs in the browser (canvas, `pdf-lib`, `pdfjs-dist`). Never upload user files anywhere.

## Verify before you commit
- `npx tsc --noEmit` passes. `npm run build` needs network for Google Fonts.
- Check in a browser at roughly 320, 768, 1440 px wide and at 50% and 200% zoom, on the home page and the passport page.
- No horizontal scrollbar, no clipped buttons, the A4 preview fully visible on first load.

## Git and secrets
- Never commit tokens, keys or `.env` files. Never put a token in a remote URL or git config.
- If a temporary token is used to push, pass it inline for that one command, then tell the owner to revoke it.
- Keep commits small, with a clear message.
